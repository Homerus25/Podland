# Frontend Conventions

How the React frontend (`frontend/src/`) is organized. System architecture lives in `docs/architecture-decisions.md`; domain language in `GLOSSARY.md`; API contracts in `doku/`. This file covers the patterns a new feature slice needs, so slices start from knowledge instead of re-reading sibling features.

Formatting is automated: a Crush pre-edit hook (`.crushrc` → `.crush/hooks/biome-format.sh`) runs Biome on a file before every edit, so files are already formatted when you read them. Run `npx biome check <changed files>` once at the end as a gate; never interleave `--write` runs with your own reads and edits.

## Feature folder layout

Each feature lives in `src/features/<name>/`:

- `services/<feature>Api.ts` — API client functions through the shared axios instance (`@shared/utils/api`), plus the **DTO response types colocated here** (see the DTO-types note at the end of this file). Machine-scoped request URLs route through the builder pair `machineApiPath`/`machineApiUrl` (`@shared/utils/api`), the single owner of machine-scoped URL construction: it percent-encodes every path segment, machineId first — services never hand-encode. Axios calls take the path form (the shared instance prepends the base); fetch consumers (stream transport, `downloadFile`) take the full form. Stream and download URLs are consumed from the owning service's export (`pullStreamUrl`, `autoUpdateStreamUrl`, `volumeExportUrl`), never re-derived in hooks or components, and importing `apiBaseUrl` outside `@shared/utils/api` is off-limits (module-private; the compiler enforces it). Settled 2026-09-15 (architecture-review candidate C11).
- `hooks/<feature>Api hooks` — React Query hooks in `use<Feature>.ts`.
- `components/` — UI components and their colocated tests.

## React Query

- Query keys come from the `shared/queries` constructors (`containersQueryKey`, `secretQueryKey`, `machineStatusQueryKey`, the `machinesQueryKey` constant, …); never build a `['machines', …]` array or a private key constructor in a feature. A new resource tab adds one `MachineResource` union member plus one plural list constructor in `queryKeys.ts`.
- List-invalidating mutations go through `useListInvalidatingMutation(machineId, resourceOrResources, run)` (`shared/queries`); cross-feature or streaming invalidation calls `invalidateMachineResources(queryClient, machineId, resourceOrResources)`. The factory is machine-scoped by design: an app-wide resource has no machine to scope to, so a feature whose mutations invalidate one app-wide shared key keeps a feature-local invalidating-mutation wrapper over that key instead of forking the factory (`useUsersInvalidatingMutation` in `features/users/hooks/useUsers.ts` over `usersQueryKey` is the reference). No optimistic updates (matches backend "list reflects server state" simplicity).
- Detail views that must always refetch use `gcTime: 0`. Values that must never be cached (revealed secrets) travel through `useMutation`, not `useQuery`.

## Components

- Every table-backed resource list renders through `ResourceList` (`@shared/components/ResourceList`), the one owner of the list machinery: the loading/error/empty/table triad, the Chakra table chrome, the plural testid derivation (`{resource}s-loading`, `-error`, `-empty`, `-table`), the toolbar wrapper, and the permission hint. The triad itself is single-owned one level down, in `ResourceStates` (`@shared/components/ResourceStates`) — the headless loading/error/empty owner `ResourceList` composes for its triad branch, and non-table collection sites (card grids, grant rows) render through it directly instead of hand-deriving the ritual. It renders the three states and takes `children` for the populated state, owning the triad JSX, the copy defaults, the styling, and the testid derivation; it is deliberately non-generic (`items: readonly unknown[] | undefined` — the module never reads item shape, and undefined counts as empty) and has no loading-copy override. It is for collections, not detail views: single-item loading/error with no empty semantics (machine detail, quadlet edit, secret detail) does not fit `items`. Settled 2026-10-01 (2026-09-22 architecture-review candidate 8). A feature list is an adapter: it keeps its query and mutation hooks and hands over resolved state — `resource` (plural noun), `isPending`, `error`, `items`, `columns` (data, not JSX: `{ label?, isNumeric? }[]`; a label-less entry renders the bare action-column header), `renderRow`, and optionally `toolbar`, `canManage`, `emptyMessage`. `SecretList` (`src/features/secrets/components/SecretList.tsx`) is the smallest reference adapter; a new resource tab copies it, not the machinery.
- The triad is **inline, never an early return**: the toolbar (or hint) renders above the state ternary, so toolbar and hint stay reachable while loading, on error, and when empty. Do not add a loading early-return to a list component.
- Errors render via `ErrorDisplay` with `getApiError(error)`; it accepts extra props (e.g. `data-testid`) and spreads them onto the alert. `ResourceList` uses it for the list-level error state; feature code keeps it for row- and dialog-level errors.
- Every mutation dialog renders through the shared dialog module at `@shared/components/MutationDialog`: form dialogs through its `FormDialog` preset, destructive confirms through its `ConfirmDialog` preset (ghost cancel, red confirm with the `confirm-delete-button` testid, pending wired). The module owns the machinery every dialog used to hand-roll: the modal shell, the reset invariant (`reset()` runs on mount and unmount; consumers render the dialog conditionally, so mount is open and unmount is close, and reopening always starts clean), pending wiring, close-on-success, and the in-modal error region. It never touches react-query: the caller keeps its mutation hooks (and invalidation choices) and hands over the result's structural slice `{ mutate, isPending, error, isSuccess, reset }`. Settled 2026-09-11 (architecture-review candidate C6).
- Stay-open report dialogs — a mutation whose success payload is rendered in place (prune) — ride `PruneReportDialog` (`@shared/components/PruneReportDialog`), standalone from `MutationDialog` because the two disagree on the headline invariant (stays open on success vs closes on success). It owns the reset lifecycle, the confirm/report footer swap, the report table (mono label cell, red error cell vs `formatBytes`), the empty-report and confirm copy derived from the singular `resource` noun, and the error region. The caller hands over the structural slice plus the success payload (`data: TEntry[]`), the noun, and the two entry accessors `entryKey` and `renderLabel`; the images prune adapter in `ImageList` is the smallest reference adapter. Toolbar labels stay feature-owned — they live outside the dialog.
- Stay-open transfer dialogs — a cross-machine move/copy whose success narrates in place (quadlet, volume, secret) — ride the transfer-dialog preset at `@shared/components/TransferDialog`, the third dialog shape after `MutationDialog` and `PruneReportDialog` (issue 238's per-feature ruling ended when the third surface arrived; settled 2026-10-05, issue 241). The preset splits in two: `useTransferState(machine, capability)` owns the state half — the capability-filtered target list (source excluded), the selected target defaulting to the first, and the mode defaulting to Move — and `TransferDialog` owns the render half: the target select, the mode radio, the target-scoped preview's pending/error/collision states, the referencing-quadlet warning, the confirm/report footer swap, and the in-modal error region with the `renderHints` seam (error-code hints live there, the `renderError` precedent). Like `PruneReportDialog` it stays open on success — a partial result names the both-machines state — but the report node is the caller's: the adapter hands over `report` and decides what narrates, so a mixed success behavior (the quadlet's file-only close) stays feature-owned. The adapter calls `useTransferState` first (its preview hook needs `targetId`), keeps its domain in two body slots — `warnings` renders between the collision block and the referencing warning, `children` after it, preserving each surface's warning order — and passes `reset` only for a caller-owned mutation that outlives the dialog (component-local hooks die with it; the effect keys on the reference, so it is a react-query mutation's stable `reset`). The feature keeps its preview query key's constructor and fetcher and its mutation or stream hook as a thin adapter over the shared transfer-hooks module (`@shared/transfers`; settled 2026-10-13, issue 273, 2026-10-08 architecture-review candidate 5) — the module owns the preview ritual (the null-target guard, the empty-string placeholder key, the enabled gate), the both-machines invalidation, and the move-stream lifecycle, while the feature keeps its domain: the event vocabulary, shape guard, progress fold, and URL builder. The machines query inside `useTransferState` is the one query the preset owns. `MoveSecretDialog` is the smallest reference adapter.
- The connect ritual — attaching a running container to a network — has one owner: `ConnectDialog` in the networks feature (`@features/networks/components/ConnectDialog`), discriminated by the fixed side (the Networks tab passes the network and the dialog picks the container; the Containers tab passes the container and the dialog picks the network). The dialog fetches its own options and drives the connect mutation itself, including the both-lists invalidation that rides the mutation; the two list surfaces shrink to a row button, the fixed side, and a close callback. The containers feature calls into the networks feature for connect, never the reverse, and the networks feature imports nothing new from containers for it. Settled 2026-10-13 (2026-10-08 architecture-review candidate 6).
- Side effects are explicit at each call site through the seams: `onSuccess` fires exactly once before the module closes the dialog (a toast, a navigate-away, or a silent close is a per-site choice, never a copy-paste accident), and `onError` fires on failure while the dialog stays open. A form's submit handler just calls `mutate`: forms no longer await their mutations and carry no internal error JSX or reset calls.
- The error region renders `ErrorDisplay` with `getApiError(error)` under the `mutation-dialog-error` testid by default; `renderError` replaces the whole region, and that is where error-code-to-hint mapping lives as feature adapters (volume composes the default display plus its in-use hint, image returns only the in-use hint, populate maps `VOLUME_UPLOAD_TOO_LARGE`). On `ConfirmDialog`, `renderConfirm` replaces the confirm button itself (image's `confirm-delete-button` to `force-delete-button` swap driven by the error).
- The dialog module owns every confirm and form footer, extending the C6 settlement. Destructive confirms keep riding `ConfirmDialog`, now with `confirmColorScheme`/`confirmTestId` knobs so "confirm-with-variables" stops meaning "destructive" (defaults stay the red `confirm-delete-button` look, byte-identical). Confirms that perform a caller-owned action instead of a mutation ride `ActionDialog` — shell + ghost Cancel only: no pending wiring, no error region, no auto-close; the caller closes in `onConfirm` (the update-all pre-flight is the reference). Form dialogs ride `FormDialog` with fields-only bodies: the body's form carries the id and its submit handler just calls `mutate`; the footer's blue submit is associated by native form id, and one submit policy holds everywhere — disabled while the published form state (`FormValidityScope`, passed straight from the form library's `formState`) is invalid or submitting, or while the mutation is pending. The formerly ungated forms (create container, quadlet create/edit, add machine) validate on change now, so their buttons start disabled — a deliberate normalization, not drift. The one non-dialog form site (the machine settings inline form) joins through the composable `FormFooter` without a shell: it keeps submit-time validation, its submit gates on the host mutation's `pending` — the single prop the site keeps because its mutation lives in the host tab — and its Cancel (opt-in `cancelTestId`, `machine-form-cancel` there) reverts the fields to the stored seed and fires the host's cancel seam, whose mutation reset clears both the error text and the "Changes saved" banner; cancel stays enabled while a save is in flight, and because a cancelled save still runs to completion server-side, the host tab suppresses that late settle so neither banner nor error resurrects over the reverted fields. Skeleton and invariant behavior of all these surfaces is pinned once in `shared/components/MutationDialog.test.tsx`; feature suites keep domain assertions only. Settled 2026-09-25 (2026-09-22 architecture-review candidates 3 and 7).
- Reference adapters: `SecretList`'s delete confirm is the smallest confirm; `MachinesPage`'s add-machine modal is the smallest form host. Copy those, not the machinery. Non-modal mutation sites (secret reveal, share grant/revoke, the pull-image toolbar) keep feature-local resets; they share no dialog skeleton with the module — the machine settings inline form is the exception that rides the composable `FormFooter` (2026-09-25 settlement above).
- Rows are feature-rendered: the Row component owns the singular `data-testid` (`<item>-row`) so tests use `within(row)` for per-row assertions. When several of a list's rows render on one page (the users directory), the testid carries the row's unique key — `user-row-${username}`, the `grant-row-${id}` precedent — so tests still select one row. A clickable row keeps its `onClick` in the feature's row, and the action buttons inside such a row call `stopPropagation` so a button click does not also fire the row action.
- Dates via `formatRelativeDate`, byte sizes via `formatBytes` (`@shared/utils/format`).
- Hide-and-hint for resource lists is module-owned: pass `canManage` (computed with `can(machine, capability)` from `@features/machines/permissions`, one predicate over the capability table mirroring the backend's enforcement); when false, `ResourceList` hides the toolbar and renders the canonical hint through the shared `PermissionHint` (`@shared/components/PermissionHint`) — "You have read-only access to this machine. Ask an owner or admin for write access to manage its {resource}s." — carrying `{resource}s-permission-hint` and `data-requirement="write"`. `PermissionHint` owns every hint sentence, the derived `{scope}-permission-hint` testid, and the `data-requirement` attribute (write, admin, owner); never render a feature-private variant of any hint and never ship disabled buttons. Every machine-scoped list whose resource has write-level routes has a permission concept and passes `canManage` — containers included: its create/start/stop/delete routes are write-gated, so a read-level grantee gets the hint, not the toolbar. A read-only slice (no mutation routes yet) takes only `machineId` and passes no `canManage` — no hint, ever; `NetworkList` is the reference adapter.

## Streaming

- Every streaming endpoint rides the stream transport module (`@shared/streaming/streamTransport`); no feature hand-rolls a streaming fetch, an abort lifecycle, or a terminal guard. The two layers split by streaming shape: operation streams — a start/cancel lifecycle whose backend ends runs with a terminal `complete`/`error` event (image pull, quadlet auto-update) — use the `useNdjsonOperation` hook, which owns the abort, the supersede rule (a new start aborts the old run, whose late events reach nobody), exactly-one-terminal, and the running/error state; signal-driven follow streams without operation semantics (log following) call the `streamNdjson` function directly and pass their own `AbortSignal`. A feature keeps only its event handlers, shape guards, and invalidation choices — the Bearer preamble, the error envelopes, the abort teardown, and the NDJSON consume loop (malformed lines warned and skipped) are the module's. Blob downloads stay out: bytes carry no abort/supersede ritual and do not fit an NDJSON interface. Settled 2026-09-12 (architecture-review candidate C1).
- Log-bearing features ride the log-source factory (`@shared/streaming/logSource`): the feature's service resolves the machine-scoped path/url pair through the builder pair (`machineApiPath`/`machineApiUrl`) and exports a one-line `LogSource` builder handing both forms to `createLogSource` (`containerLogs`, `quadletLogs` are the reference adapters); the factory owns the rest of the log-endpoint ritual — the buffered tail fetch with its split-and-filter parse, the URLSearchParams follow query, and the `ApiError` wrap, with follow riding `followLogStream` on the stream transport. The `LogSource` contract and the buffered-logs DTO live in the kit; features keep only target resolution, and hand-concatenated log query strings are off-limits (`?tail=..&follow=true` died with the four twin functions). Feature logs suites keep one wiring smoke each — list renders, the logs button navigates to the logs page, the feature's own endpoint gets the request, history lines render — because tail/query/error invariants are pinned once in `logSource.test.ts` and viewer machinery once in `LogViewer.test.tsx`. The logs page picks its source from a record exhaustive over `LogKind`, so a future log-bearing kind is a type error until it gets an entry; URLSearchParams is the precedent for future stream query construction. Settled 2026-09-18 (architecture-review candidate C19).
- The logs **route** contract is one kit, `@shared/logs/logRoute`: it owns the `LogKind` union with its `isLogKind` guard, the `LOG_ROUTE_PATTERN` route constant (mounted by the app router and by both feature logs test renderers — no logs route or path literal lives outside the kit), the `logsPath` builder (percent-encodes `machineId` and `targetId`, extending the C11 machine-scoped URL discipline to the one machine-scoped URL family it did not cover; the router decodes params on the far side), the typed `LogsPageState` navigation state, and the `useOpenLogs(machineId, kind)` hook that binds the kind once per feature — the twin `useOpenContainerLogs`/`useOpenQuadletLogs` hooks died with it. A new log-bearing kind is one `LogKind` member plus one `LOG_SOURCES` entry in the logs page. The C19 `logSource` kit is untouched by design: that kit owns fetching, this one owns navigation (the `LOG_SOURCES` record stays with the logs page because it needs the feature services; the dependency direction stays features → shared). The path shape and the encoding round trip are pinned once in the kit's suite. Settled 2026-10-01 (2026-09-22 architecture-review candidate 9).

## Auth and 401s

- "Refresh the session" has one owner, `refreshSession()` in `@shared/utils/api`: it alone assembles the POST literal, installs the fresh token, and holds the single flight every caller shares; success resolves the payload, any failure (auth rejection or network) resolves `null` without throwing or firing the seam. Its two thin callers are `AuthContext`'s default `resolveInitialState` resolver (mount restore) and `handleUnauthorized()` — only the 401 policy translates `null` into `fireSessionExpired()`, since a mount failure is logged-out, not session death. Never re-assemble a refresh elsewhere or keep a second vocabulary for the same act (`authApi.refresh` was deleted outright for exactly that). Settled 2026-09-18 (architecture-review candidate C18).
- 401s are owned by the shared session policy, never by a feature: the axios response interceptor on the shared instance (`@shared/utils/api`) and the stream transport both route through `handleUnauthorized` — single-flight refresh, replay once, session death when refresh or replay fails. The refresh/replay/seam semantics are pinned once in the shared suites (`shared/utils/api.test.ts`, `shared/streaming/streamTransport.test.tsx`, and the session-death wiring test in `App.test.tsx`); feature suites never pin 401 behavior or add their own expiry handling. File downloads stay outside the policy by decision.

## Tests

- Vitest + Testing Library + MSW. Global handlers in `src/test/handlers.ts` cover only auth/health/status; **each test overrides its endpoints with `server.use(http.get('*/api/...', ...))`** using a `*Fixture()` helper building a typed object with `Partial` overrides. Shared fixture factories live in `src/test/factories.ts` — import from there instead of re-declaring a `*Fixture()` per test file; add a new factory there when a DTO is first tested. Error envelopes come from `errorJson`/`errorResponse`/`axiosError` (`@/test/errors`), never hand-written literals. The harness-and-builders adoption arc is expand-then-adopt — owner first and pinned, then mechanical migration with assertions untouched; settled 2026-09-19 (architecture-review candidate C20).
- The full suite is a gate that must actually finish: it completes in under 2 minutes on a healthy tree (`npx vitest run`). During a change, run only the affected test files; run the full suite once at the end. A run that hangs or stretches past that is a bug to diagnose immediately, not a wait — a starved worker means an effect/async loop is blocking the event loop (see the LogViewer incident: unstable callback identities in a `useEffect` dep array).
- **List triad behavior is pinned once, in `shared/components/ResourceStates.test.tsx`**: mutual exclusion of the loading/error/empty/children states, plural testid derivation, the default and overridden empty copy, children-only-when-populated, and undefined = empty. `shared/components/ResourceList.test.tsx` keeps the toolbar/hint swap, the columns/chrome pins, and one composition smoke (the triad routing through `ResourceStates`). A feature list suite keeps one loading smoke test (adapter wiring: the loading state renders with the toolbar still above it) plus all row/action/domain assertions; it consumes the derived testids as fixtures and does not re-pin exclusion.
- **Dialog skeleton and invariant behavior is pinned once, in `shared/components/MutationDialog.test.tsx`** (a stub mutation object, no QueryClient): reset on mount and unmount, cancel-sends-nothing, pending disables confirm, the default error region, close-on-success with the `onSuccess`/`onError` seams fired exactly once, and both replacement seams (`renderError`, `renderConfirm`). Feature dialog suites drop their skeleton re-pins (cancel, pending, generic in-modal error) and keep domain assertions: force/stop parameters, error-code hints and envelopes, row removal, toasts, navigate, read-user gating.
- **Stay-open report dialog behavior is pinned once, in `shared/components/PruneReportDialog.test.tsx`** (a stub mutation object, no QueryClient): reset on mount and unmount, the confirm/report footer swap, cancel-sends-nothing, stays-open-on-success, the report table and empty-report copy, the noun-derived copy, and the error region. Prune feature suites drop their report-detail re-pins (per-entry errors, empty-report copy) and keep read-level gating, one adapter-wiring smoke (opens the confirm, sends nothing), and the domain flow (request shape + list refetch through MSW).
- **Transfer-dialog skeleton behavior is pinned once, in `shared/components/TransferDialog.test.tsx`** (a stubbed machines hook and preview slice, no MSW): the capability filter with source exclusion, the default target and mode, the noun-derived copy (mode radio, confirm button, collision, referencing, empty picker), the confirm disabled set, the error region with the hint seam, the footer swap on the stay-open report, the two body slots' order, and the reset seam. Move feature suites keep domain assertions — request shapes and mode-gated flags, error-code hints, report and narration contents, invalidation through MSW — plus their preview-state smokes (pending, failed preview, collision) as adapter wiring through their own endpoints, the list-suite precedent: the feature's preview hook feeding the shared skeleton, not a skeleton re-pin.
- **Stream-transport invariants are pinned once, in `shared/streaming/streamTransport.test.tsx`**: Bearer header, content-type-only-with-body, non-ok and no-body envelopes, abort-is-not-an-error, supersede, exactly-one-terminal, and malformed-line skipping plus split reassembly. Feature streaming suites drop their transport re-pins and keep domain assertions: request shape, progress/report exposure, invalidation including the dry-run skip, error-event routing. The move/copy streams are the exception — their lifecycle (terminal handling, error-event routing, and the both-machines invalidation) is the transfer-hooks module's (issue 273), pinned once in its suite, so a move stream suite keeps only the request shape and the progress fold. Log-bearing feature suites stop at the one wiring smoke the Streaming section defines — log-event filtering and error-event parsing are pinned in the log kit and viewer suites, not theirs. One adapter-wiring smoke case per feature may stay even where the module also pins it (e.g. pull's non-ok envelope routing).
- Component and hook tests render through `renderWithQuery(ui, { router?, chakra? })` / `renderHookWithQuery` (`@/test/render`); never hand-roll a provider stack.
- Test seams are the public interface (hook return value, rendered DOM), never internals.
- Query invalidation is asserted at the factory test (`useListInvalidatingMutation.test.tsx`, the sanctioned `vi.spyOn(queryClient, "invalidateQueries")`); feature tests assert refetch through MSW instead of invalidation spies. Streaming-hook tests keep their invalidation spies — the dry-run skip is bespoke logic nothing else covers.
- **Multipart/upload endpoints: MSW cannot consume FormData bodies in this environment** — any handler that reads the body (`request.formData()`, `request.text()`, …) hangs, and axios POSTs of FormData hang with it. Instead: extract the payload building into a pure function (e.g. `buildPopulateForm`) and unit-test that; in component tests, mock the single API function with `vi.mock` (partial mock keeping the rest of the module real) and note why. See `volumesApi.populate.test.ts` + `VolumeList.populate.test.tsx`.
- Cross-realm caveat when asserting on parsed multipart parts outside this limitation: MSW parses bodies with its own `File`/`Blob` implementations, so `instanceof File` fails — check for `"name" in part` instead.
- AbortSignal cross-realm caveat: under jsdom, `AbortController`/`AbortSignal` globals are jsdom's, and Node >= 24 (undici 7) rejects them in `fetch` (`instanceof` brand check), while DOM listeners (framer-motion) reject Node's — so neither global swap works. `src/test/setup.ts` installs a fetch relay after `server.listen` that passes a Node-realm signal to the fetch stack; don't create `fetch` calls with hand-built signals that bypass it, and don't swap the globals back.

## Machine detail page

Tabs in `pages/MachineDetailPage.tsx`: Containers, Volumes, Images, Networks, Quadlets, Secrets, Settings. A new resource tab goes in epic-specified position; read-only slices take only `machineId`, permission-gated slices take the `machine` and gate with `can(machine, capability)`. The tab's list component is a `ResourceList` adapter — copy the smallest existing one (`SecretList`), never hand-roll list machinery.

DTO types and their field vocabularies (e.g. quadlet states: `unknown | stopped | running | error`; resources: container, pod, image, volume, network) are defined in each feature's `services/<feature>Api.ts` — read that file before writing tests or conditional UI against a resource's state.
